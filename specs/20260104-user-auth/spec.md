## Overview

实现用户注册和登录功能，允许用户使用手机号码或邮箱进行账号注册，并通过账号和密码完成登录认证。系统需要验证用户输入的合法性、唯一性，并确保用户凭证的安全存储。

---

## User Stories

### Story 1: 用户注册 (P1)

AS a 未注册用户
I WANT 使用手机号码或邮箱注册账号
SO THAT 我可以访问系统的受保护资源

**独立测试**: 用户可以成功提交注册表单，收到注册成功响应，并能使用注册的账号登录

### Story 2: 用户登录 (P1)

AS a 已注册用户
I WANT 使用注册的账号和密码登录
SO THAT 我可以访问我的个人数据和系统功能

**独立测试**: 用户可以提交正确的账号和密码，收到登录成功响应，并获得访问权限

## Acceptance Criteria (EARS)

### 正常流程

| ID | Scenario | Trigger | Expected Behavior |
|----|----------|---------|-------------------|
| AC-01 | 手机号注册成功 | WHEN 用户提交有效的手机号和密码 | THE SYSTEM SHALL 创建账号，返回成功响应 |
| AC-02 | 邮箱注册成功 | WHEN 用户提交有效的邮箱和密码 | THE SYSTEM SHALL 创建账号，返回成功响应 |
| AC-03 | 手机号登录成功 | WHEN 用户提交正确的手机号和密码 | THE SYSTEM SHALL 验证通过，返回认证凭证 |
| AC-04 | 邮箱登录成功 | WHEN 用户提交正确的邮箱和密码 | THE SYSTEM SHALL 验证通过，返回认证凭证 |

### 异常处理

| ID | Scenario | Trigger | Expected Behavior |
|----|----------|---------|-------------------|
| AC-10 | 手机号格式错误 | WHEN 提交的手机号格式无效 | THE SYSTEM SHALL 返回 400，提示格式错误 |
| AC-11 | 邮箱格式错误 | WHEN 提交的邮箱格式无效 | THE SYSTEM SHALL 返回 400，提示格式错误 |
| AC-12 | 密码强度不足 | WHEN 提交的密码不符合强度要求 | THE SYSTEM SHALL 返回 400，提示密码要求 |
| AC-13 | 手机号已被注册 | WHEN 提交已存在的手机号 | THE SYSTEM SHALL 返回 409，提示已注册 |
| AC-14 | 邮箱已被注册 | WHEN 提交已存在的邮箱 | THE SYSTEM SHALL 返回 409，提示已注册 |
| AC-15 | 账号或密码错误 | WHEN 登录时账号不存在或密码错误 | THE SYSTEM SHALL 返回 401，提示认证失败 |
| AC-16 | 参数为空 | WHEN 必填参数为空 | THE SYSTEM SHALL 返回 400，提示缺少参数 |
| AC-17 | 账号不存在 | WHEN 使用未注册的账号登录 | THE SYSTEM SHALL 返回 401，提示账号或密码错误 |

## Edge Cases

| ID | Case | Expected Behavior |
|----|------|-------------------|
| EC-01 | 同一手机号重复注册 | 仅第一次成功，后续返回 409 |
| EC-02 | 同一邮箱重复注册 | 仅第一次成功，后续返回 409 |
| EC-03 | 手机号和邮箱已被其他账号使用 | 返回 409，提示具体冲突项 |
| EC-04 | 并发注册相同账号 | 仅一个成功，其他返回 409 |
| EC-05 | 密码包含特殊字符 | 正常处理，支持特殊字符 |
| EC-06 | 账号输入大小写 | 邮箱不区分大小写，手机号保持原样 |

## Business Rules

| ID | Rule | Description |
|----|------|-------------|
| BR-01 | 账号唯一性 | 手机号和邮箱在系统中必须唯一，不能重复注册 |
| BR-02 | 密码强度 | 密码长度 8-32 位，必须包含字母和数字 |
| BR-03 | 手机号格式 | 支持中国大陆 11 位手机号（1 开头） |
| BR-04 | 邮箱格式 | 符合标准邮箱格式（user@domain.tld） |
| BR-05 | 密码存储 | 密码必须使用不可逆加密存储，不得明文保存 |
| BR-06 | 登录凭证 | 登录成功后颁发有效期的访问凭证 |

## Data Considerations

| Field | Description | Constraints |
|-------|-------------|-------------|
| 账号标识 | UUID 主键 | 必填，全局唯一 |
| 手机号 | 用户手机号 | 可选，11 位数字，唯一 |
| 邮箱 | 用户邮箱 | 可选，标准邮箱格式，唯一 |
| 密码哈希 | 加密后的密码 | 必填，不可逆加密 |
| 账号状态 | 账号启用状态 | 正常/禁用，默认正常 |
| 注册时间 | 账号创建时间 | 自动记录 |
| 最后登录时间 | 最近一次登录时间 | 自动更新 |

**注**: 手机号和邮箱至少填写一个

## Assumptions

1. **密码加密算法**: 使用 bcrypt 或 Argon2 进行密码哈希
2. **认证凭证**: 使用 JWT (JSON Web Token) 作为登录凭证
3. **Token 有效期**: Access Token 有效期 2 小时，支持刷新机制
4. **手机号验证**: 暂不要求短信验证码，仅格式验证
5. **邮箱验证**: 暂不要求邮箱验证链接，仅格式验证
6. **账号类型**: 默认为普通用户，暂不支持角色权限
7. **并发控制**: 使用数据库唯一索引保证账号唯一性
